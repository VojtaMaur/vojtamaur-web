## Proč se zastavil

Požadavek `AGENT-005:8` měl limit 3 hosted tool calls. V odpovědi jsou tři
`web_search_call` se `status=completed` a čtvrtý se `status=searching`, bez
výsledkových sources. Framework započítal všechny čtyři. Tokeny 22 336 se vešly
do rezervace 439 880; problém byl pouze počet hledání 4 > 3. Záznam se stal
UNKNOWN a zablokoval celý roj, přestože zbývalo dost z celkových 3 milionů tokenů.

API specifikace uvádí, že `max_tool_calls` omezuje zpracované built-in volání
a další pokusy ignoruje. Čtvrtý zaznamenaný pending pokus interpretujeme jako
takový ignorovaný pokus; neposuzujeme jej jako dokončené hledání.
[OpenAI Responses reference](https://developers.openai.com/api/reference/python/resources/responses/methods/create).
Nejde o nezávislé potvrzení billing položek na provider účtu.

## Opravy 0.3.2

- Stejná klasifikace v SDK čítači i v host settlement: pending search bez výsledku
  po dosažení přesného capu se audituje zvlášť. Chybějící/failed/neočekávané
  hledání a skutečné překročení zůstávají konzervativní; UNKNOWN se nemaže.
- Skutečně UNKNOWN request zastaví scheduler před další rolí, zachová pending
  práci a hlásí BLOCKED s příčinou. Nevytváří kaskádu dalších blokovaných agentů.
- Paměť obsahuje strukturovaný seznam všech zachycených kandidátů v mezích limitů,
  jejich původní run/IDEA, provider, mechanismus, stav a další krok. Nástroj
  `check_prior_work` hledá tento seznam před discovery.
- Výzkumný profil používá `prior_work_policy=novelty-first`. Opakovaný nezměněný
  mechanismus discovery vrátí DEFERRED s provenance; není novou IDEA ani REJECTED.
  Koordinační role v tomto režimu nevyrábějí discovery kandidáty. Local Prototyper
  může pokračovat ve skutečně nedokončeném testu a nový lokální kandidát nese
  `prior_work_refs`. Režim continue je explicitní možnost pro cílené navázání.
- QR/XMP composite card se identifikuje před ORCID directory pravidlem. Dvě
  doložené scope formulace karty se sloučí, skutečně odlišné scopes zůstávají
  oddělené. Public ORCID pointer scope aliases se také sjednotí.

Původní ledger, ID, report a receipts nebyly upraveny. Replay jeho skutečné
odpovědi a dvou kandidátů: `docs/validation/GENERATION_REPLAY.json`.
Nové regresní testy obsahují reprodukci tohoto tvaru odpovědi, reálný SDK s
injektovaným modelem, cross-run deferral, provenance, local continuation a
zastavení scheduleru při skutečném UNKNOWN. Žádné placené API volání.
